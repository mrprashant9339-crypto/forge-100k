# Forge 100K — Local-first 3D Character & Asset Library

Forge 100K is an original procedural 3D character catalogue and Blender generation pipeline. The catalogue contains 100,000 deterministic combinations; it is not a claim that 100,000 unique AAA models have already been generated.

## Fully local mode (recommended)

The local stack removes Supabase, Cloudflare Workers, D1, R2 and remote auth/storage from the runtime:

- Web + API: Python standard-library HTTP server on http://localhost:8000
- Database: SQLite with WAL, stored in Docker volume forge-data
- Assets: private local filesystem storage in the same volume
- Authentication: local email/password accounts, PBKDF2 password hashes, HttpOnly/SameSite session cookies
- Queue: SQLite-backed job queue with worker leases and retry handling
- Generation: local Blender worker; GLB files are validated and stored locally
- Presets: local SQLite per-account persistence, plus browser guest presets

### Requirements
- Docker Engine + Docker Compose plugin
- 16 GB RAM recommended for Blender workloads
- CPU-only generation works; a supported GPU is optional
- Blender is installed inside the worker container

### Start

```bash
cp .env.local.example .env
# Replace FORGE_WORKER_TOKEN with a strong random value (e.g. openssl rand -hex 32)
docker compose -f docker-compose.local.yml up --build -d
```

Open http://localhost:8000. Check health at http://localhost:8000/api/health.

### Stop / data management

```bash
docker compose -f docker-compose.local.yml down
# Persistent local database and assets remain in the named volume.
docker compose -f docker-compose.local.yml down -v
# WARNING: the command above permanently deletes the local database and generated assets.
```

View logs:

```bash
docker compose -f docker-compose.local.yml logs -f api worker
```

### Queue generation
The local API accepts authenticated character generation jobs at POST /api/jobs. The server binds each job to the signed-in account. The browser cannot choose another user's ID. The worker supports original procedural character jobs targeting glTF2 at blockout quality. Jobs are queued in SQLite, generated by Blender, structurally validated, then written to the private local asset directory.

### Security and operational notes
- Compose publishes the API only on loopback (127.0.0.1:8000). Do not expose it to a LAN or internet without TLS, CSRF protection, rate limits and a hardened reverse proxy.
- Keep .env private. The worker token is service-to-service only.
- Passwords are PBKDF2-HMAC-SHA256 hashed; session tokens are stored as SHA-256 hashes and expire after 14 days.
- Local password recovery does not send email.
- Back up the Docker volume before upgrading or moving machines.
- The backend, auth, queue, database and storage are local. The existing browser Three.js CDN dependency must be vendored for a genuinely air-gapped install.
- This is a single trusted workstation setup, not a hardened public multi-user service.

## Existing features
- Deterministic 100,000-entry catalogue with search, category filters and pagination.
- Interactive Three.js viewport with orbit and zoom.
- Outfit, body-form and palette controls.
- GLB export and GLB upload preview.
- Local accounts, saved presets, queue and asset storage.
- Blender procedural character blockout generation and structural GLB validation.
- Rigging, facial starter controls, animation and deformation QA scripts.

## Scope and legal note
The 100,000 entries are procedural presets, not 100,000 separately authored AAA-quality models. The current local generation worker creates starter blockout assets, not production/game-ready characters. Production release still requires real-asset review, self-intersection/cloth/pose QA, engine validation, licensing review and artist approval. Do not copy or redistribute proprietary game assets. Third-party assets must be added only after checking their licences.

## Legacy cloud mode
Supabase and Cloudflare files/migrations are retained for historical reference, but local runtime does not use them. Do not start the legacy workers/generation_worker.py worker with the local queue. Use workers/local_generation_worker.py through the local Compose stack.
